# Fixture corpus

Generated by `../make_fixtures.py` — do not edit by hand; regenerate.

Each case is a directory with a `case.json` manifest:

```json
{
  "description": "what this case proves",
  "now": "YYYY-MM-DD (the --now the expectations are stated against)",
  "days": 90,
  "expected_findings": [{"kind": "certificate|jwt|fixture-date", "status": "expired|expiring"}],
  "expected_safe": 0,
  "expected_exit": 0,
  "expected_unscanned": [],
  "expected_warnings_min": 0
}
```

Groups (22 cases):

- `clean_*` (7) — must produce **zero** findings: no artefacts, far-future
  cert, far-future JWT, far-future fixture date, historical dates in a
  changelog/docs, stamp/record dates in sample paths (the KiCad
  title-block regression case), a chained PEM of two far-future certs.
- `fault_*` (10) — exactly the planted findings, one fault per case
  (except `fault_fixture_date_expiring`, which plants the same date on two
  lines on purpose, and `fault_expired_and_expiring_mix`, which proves
  exit code 2 outranks 1).
- `edge_*` (5) — binary blob with cert-like bytes, malformed JWT-shaped
  strings, malformed PEM, a 6 MiB file (must appear as unscanned, its
  planted expired JWT must be neither found nor silently passed), and a
  filename with spaces + unicode containing an expired JWT.

Certificates are self-signed via the openssl CLI at generation time
(private keys are created in a temp dir and deleted — only certs are
fixtures). Cert `notAfter` values are relative to the generation date;
each manifest's `now` is derived from that date, so the corpus stays
correct whenever it is regenerated. The expired-cert case simulates
expiry through `--now` (+60 days) because openssl cannot mint a past
`notAfter`; the expired JWT (`exp` = 2020-01-01) and the past fixture
dates are genuinely past with no simulation.
