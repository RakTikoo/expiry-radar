# Contributing to Expiry Radar

Thanks for your interest. Expiry Radar is a small, deliberately
conservative tool — it would rather miss an exotic date format than
flag a file that is actually fine. Contributions that protect that
precision are very welcome.

## The rules of the house

1. **Standard library only.** `expiry_radar.py` must run on a stock
   Python 3.9+ install with zero dependencies, no network access, no
   account and no token. PRs that add a dependency will be declined.
2. **Deterministic.** Same input, same report. No clocks other than
   the explicit `--now`, no randomness, no environment-dependent
   behaviour (the one time that slipped in — a JSON recursion limit —
   CI caught it; see the v0.1 notes in `CHANGELOG.md`).
3. **Corpus first.** Every new detection (a format, an artefact class,
   a key spelling) starts as fixture cases under `fixtures/`:
   at least one planted-fault case that must flag, and clean / trap
   cases that must **not** flag (durations, unrelated timestamps,
   historical dates, documentation). A detection that cannot state its
   false-positive traps is not ready.
4. **Nothing sensitive is ever printed.** JWT evidence stays truncated
   and `iss` / `sub` / `aud` are never shown; JWK handling prints no
   key material. This is a hard invariant, covered by tests.
5. **Exit codes are a contract.** 0 clean, 1 expiring, 2 expired,
   3 usage error — and a broken invocation must never look like a
   finding.

## Getting started

```bash
python3 make_fixtures.py   # regenerate the fixture corpus (needs the openssl CLI)
python3 run_tests.py       # the full suite (109 tests, stdlib unittest)
```

Run the suite before and after your change; it must be green both
times. To try the scanner on a real tree:

```bash
python3 expiry_radar.py /path/to/repo --days 90
```

## Adding a fixture case

Create `fixtures/<name>/` with:

- the payload file(s) the scanner should read,
- a `case.json` stating the expected findings, safe count and exit
  code — look at an existing case (e.g. `fixtures/fault_jwk_expired/`
  or the trap case `fixtures/clean_epoch_traps/`) and copy its shape.

Name fault cases `fault_*`, clean cases `clean_*`, edge cases
`edge_*`. Certificates are generated by `make_fixtures.py`; JWTs and
dates are written literally into the payload files.

## Pull requests

- Keep the change to one topic; say what class of artefact or format
  it touches and which corpus cases prove it.
- Include the before/after suite result and, for a new detection, the
  corpus numbers (planted found, false positives on clean cases).
- Update `ANALYSIS.md` if you change a documented limitation or a
  design decision, and `CHANGELOG.md` under an "Unreleased" heading
  if the change is user-visible.

## Good first contributions

New expiry-source formats are the natural starter work — each one is
a small, corpus-first slice. Look for issues labelled
**good first issue** and **help wanted**. If a format you care about
is not listed, open an issue describing the format, a real file that
contains it, and the traps it must not flag.
